# V2 帧与素材约定

## 单一时间基准
JSON 时间线采用零基半开区间 `[start, end_exclusive)`，帧数等于差值。Blender 常用的一基闭区间对应 `[start + 1, end_exclusive]`；转成 Remotion 时 durationInFrames 等于差值，不再额外加一。

时间线以整数帧为准；秒数用于说明。30fps 下 9 秒为 frame 270，0.5 秒窗口为 15 帧。这是 NEREID 案例的数值，不是所有任务的默认参数。已有音乐与切点按用户要求保留。

## 计划检查
见 [虚构时间线示例](../examples/sequence.json)。`scripts/check_sequence.py` 检查一条完整剪辑轨的半开帧区间、空隙、重叠、未知卡片、素材长度及双层对齐字段。

转场重叠在合成层处理，剪辑轨的输出帧仍各有归属。该检查器不支持 time-warp、不同 fps 直接混用或真实媒体探测；这些情况要先明确重采样/映射计划，再形成适用的输出时间线，不能改元数据假装对齐。

## 素材和构图
- 先实际读取分辨率、fps、总帧数、起点、音轨和像素宽高比。
- 横竖输出保留完整构图；`fit: contain` 是安全的展示适配。需要裁切时必须来自任务要求并记录为 `crop-approved`，不能用拉伸填满。
- 改分辨率后抽同一源帧比较边界，确认没有把缩放写成裁切。

## 双层显色
`paired_layers` 每层记录 `camera_id / source_start / fps / width / height`。检查器只能比较这些声明是否一致；实际制作还需叠加同帧边缘，对照主体运动、场景状态和遮罩中心，避免相同标签对应不同画面。

## 声音与验收
源音频是否保留，分别核对码流/时点或允许的重新编码策略；未播放听音则不宣称主观听音通过。网页自动播放与声音按钮是播放器层行为，需要真机单独检查，不由成片音轨存在来保证。

补帧或变速先在指定关键段验证。若新帧破坏主体结构，回到干净原帧或重新设计获准范围内的运动，不把高 fps 当作唯一质量指标。
